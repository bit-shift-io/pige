# pige V1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a lightweight, MIT-licensed IMAP/SMTP mail client in Rust + iced that runs on Linux and Android, with Gmail-style conversations, folders, compose/reply/forward, search, view-only attachments, background sync and notifications.

**Architecture:** A qlaunch-style two-crate workspace. `pige_core` owns accounts, the SQLite cache, IMAP/SMTP transport, sync, threading, search, HTML sanitization, and the API snapshot/event surface. `pige` owns the iced UI, the desktop binary, and the JNI entry points. Android is a thin Kotlin shell (Activity, bridge, credentials, notifications, WorkManager) around the same Rust core.

**Tech Stack:** Rust 2024, iced (`Santuzius/iced` tag `iced_android-v0.1.1`), `iced_android` `v0.1.1`, tokio, `async-imap`, `lettre`, `mail-parser`, `rusqlite` (bundled, FTS5), `ammonia`, `html5ever`, `keyring`, `notify-rust`. Android NDK `28.2.13676358`, Gradle 9.8.1, AGP 9.4.1, minSdk 34, arm64.

**Spec:** `docs/superpowers/specs/2026-11-03-pige-email-client-design.md`

## Global Constraints

- Rust edition 2024; workspace resolver 2.
- **Multiple accounts are first-class:** every account has its own credentials, folders, UID state, threads, drafts, outbox, and unread roll-up. `sync_all` isolates failures per account; one bad login never blocks another account. The navigation rail shows "All inboxes" plus one section per account, with user-editable labels.
- **Shared component kit only:** screens compose `pige/src/components/` and read theme tokens from `theme.rs`. No screen hardcodes a colour, font size, radius, spacing value, or one-off button/field/row. This is how light/dark and later visual changes stay consistent.
- iced and `iced_android` versions, tags, and the `android-activity` patch are copied verbatim from `../qlaunch/rust/Cargo.toml`.
- Android: `bitshift.pige`, native library `pige`, minSdk 34, targetSdk 36, arm64-v8a only, NDK `28.2.13676358`, JDK 21 at `/opt/jbr-21`.
- No `melib`, no WebView, no OAuth, no background IMAP IDLE, no rich-text compose, no attachment sending in v1.
- MIT licence; copied qlaunch files carry a `// Adapted from qlaunch (GPL-3.0, same author; relicensed MIT here)` note where practical.
- `cargo test --workspace` and `cargo clippy --workspace --all-targets` are the gates.
- UI thread never does network or SQLite work; all core mutations run through `api::*` off the render thread.
- TLS only, normal certificate validation, no plaintext credential fallback.
- Breakpoints: `< 840` compact, `840–1199` medium, `>= 1200` expanded (logical points).
- Initial folder window 300 headers; "load older" pages of 100; background sync interval 15 minutes.
- Mutations apply to the conversation's copies in the current folder only; Sent copies are never collateral.
- Offline: reads, cache, search, drafts, and queued send work; other mutations are refused with a user-visible message.
- Remote images blocked by default; links restricted to `http`, `https`, `mailto`; no scripts/forms/iframes.
- Package/application id `bitshift.pige`; data/cache paths come from the platform adapter.

## Review Focus

1. **Gmail label folders with multiple labels.** Moving/archiving a conversation must not duplicate it into All Mail or delete it from labels it should keep. Tested in Task 14.
2. **UIDVALIDITY changes, expunges, and high-water drift.** A server-side mailbox reset must not leave stale messages, wrong threads, or permanently skipped mail. Tested in Task 5.
3. **Pathological HTML and remote content.** Scripts, tracking pixels, huge nesting, malformed markup, and `cid:` images must never execute, fetch, or crash the renderer. Tested in Task 9.
4. **Attachment names and MIME when opening files.** Path traversal (`../../x`), empty names, and misleading MIME types must not write outside the cache or open the wrong handler. Tested in Task 15.
5. **Offline send retry after partial success.** SMTP accepts a message but APPEND to Sent fails, or the process dies mid-send; retry must not send the message twice. Tested in Task 13.
