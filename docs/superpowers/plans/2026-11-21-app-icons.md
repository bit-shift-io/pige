# App icon (desktop + Android) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the picked app icon (`assets/app_icon_2.svg`, origami pigeon design) as the desktop window/taskbar icon and the Android launcher icon.

**Architecture:** Fix the SVG's broken drop-shadow filter reference (it makes renderers drop the bird group), rasterize it once with Inkscape into committed PNGs, embed the 256 px render in the iced shell for the desktop window icon, and reference density-specific launcher mipmaps from the Android manifest.

**Tech Stack:** Inkscape + ImageMagick for rasterization; Rust/iced (`window::Settings.icon` via `iced::window::icon::from_rgba`, decoded with the `image` crate — already in the dependency tree through iced's `image` feature); Android resources (`mipmap-*`, `AndroidManifest.xml`).

**Spec:** `docs/superpowers/specs/2026-11-21-new-mail-precache-and-icons-design.md` (Task 2 section)

## Global Constraints

- Icon source of truth: `assets/app_icon_2.svg` (user-picked). No design changes beyond removing the broken filter reference.
- Desktop icon decode failure must return `None` from the helper — it must never block or crash startup.
- Android gets plain launcher PNGs in `mipmap-{mdpi,hdpi,xhdpi,xxhdpi,xxxhdpi}` at 48/72/96/144/192 px (no adaptive-icon layers — spec non-goal).
- Committed PNGs only (no build-time SVG tooling dependency); Inkscape is used once, locally, to generate them.

## Review Focus

- **Broken filter regression:** the committed SVG must render the bird in plain renderers (strip `filter="url(#shadow)"` AND the now-unused `<filter id="shadow">` def). Pinned by the visual re-render check in Task 1 Step 3.
- **Wrong pixel density on Android:** each mipmap file must be exactly its density's size. Pinned by `magick identify` in Task 3 Step 3.
- **Startup resilience:** a corrupted embedded PNG must leave `window_icon()` returning `None` without panicking. Pinned by the decode test in Task 2.
- **Android surface untouched:** the window icon code must compile to `None` on Android (`cfg`), since iced_android manages its own surface. Pinned by Task 2 Step 4's Android-targeted check.

- [ ] **Step 3: Implement** — in `rust/pige/Cargo.toml` under `[dependencies]` add:

In `rust/pige/src/app.rs`, next to `App::new`:

```rust
/// The committed 256 px render of the app icon, embedded at compile time.
pub(crate) const APP_ICON_PNG: &[u8] = include_bytes!("../../../assets/app_icon_256.png");

/// The desktop window icon. A decode failure returns `None` rather than
/// blocking startup; Android ignores window icons and takes its launcher
/// icon from the manifest, so this stays `None` there.
#[cfg(not(target_os = "android"))]
pub(crate) fn window_icon() -> Option<iced::window::Icon> {
    let decoded = image::load_from_memory(APP_ICON_PNG).ok()?.to_rgba8();
    let (width, height) = decoded.dimensions();
    iced::window::icon::from_rgba(decoded.to_vec(), width, height).ok()
}

#[cfg(target_os = "android")]
pub(crate) fn window_icon() -> Option<iced::window::Icon> {
    None
}
```

and in `App::new` change the window opening to:

```rust
let (_id, open) = window::open(window::Settings {
    size: Size::new(900.0, 700.0),
    icon: window_icon(),
    ..Default::default()
});
```
